# PLAN.md — Pre-Rewrite Cleanup, Iteration 1: Remove Unused Features

## Context & Goal
Per `REWRITE.md`, this cleanup trims the JVM baseline BEFORE the rewrite phases so less code is ported. End state: a **single-player Commander (EDH)** experience (no Brawl/Oathbreaker/Tiny Leaders/Commander variants.

**KEEP (do not touch):** core Commander rules/gameplay, AI players, game UI/navigation, preferences for surviving features, deck editor + saved decks, in-turn undo, "Provide Deck URL", Moxfield/Archidekt import, card art fetching, deck validation, audio.

## Confirmed Decisions
1. Remove BOTH the interactive tutorial and the static `res/howto.txt` doc (stale 1v1-vs-computer intro) + its Help-menu entry.
2. Keep `DialogDownloadCardImages` + the first-run bulk-CDN-sync prompt in `FView` (card-art UX); reword the prompt text that references the removed section.
3. Lobby slot panels show the slot's **selected deck's commander card image**, falling back to the generic player icon (`FSkinProp.ICO_PLAYERS`) when no deck is selected.
4. "Bracket/banlist validation" = the Commander **bracket** (EDHREC-style skill-tier) system. Per-format **banlist** validation (`GameFormat.bannedCardNames`, `DeckFormat.isLegalCard/isLegalCommander`, `DeckRecognizer.isBannedInFormat`, `res/formats/**`) is separate and STAYS.
5. `res/lists/commander-bracket-combos.txt` feeds AI two-card-combo knowledge (2,176 pairs via `FModel` → `AiCardLists`); AI is a KEEP feature → keep the data, rename to `commander-combos.txt` (+ constant `COMMANDER_COMBOS_FILE`).

## Part 2 — Team Selection, Team Gameplay Logic, Variant Prefs & UI

### Scope (this part)
- **IN:** (1) team selection — lobby UI, slot data model, network event; (2) team gameplay logic — all shared-team-turn / Two-Headed-Giant mechanics incl. `GameType.TwoHeadedGiant`; (3) preference options for removed variants (Brawl/Oathbreaker/Tiny Leaders deck-state prefs); (4) UI elements for removed variants (format-dropdown entries, lobby Variants checkboxes, lobby team/scheme panels, deck-editor variant tabs, deck-chooser branches, `DeckType` entries, orphaned i18n keys).
- **OUT (later parts):** `GameType` entries + rule code + `DeckFormat` for Brawl/Oathbreaker/Tiny Leaders/Archenemy/ArchenemyRumble (staying entries keep their `lbl*` name/desc keys); Archenemy scheme-game engine + scheme-deck storage (`FModel.getDecks().getScheme()`, `DeckProxy.getAllSchemeDecks`, `CEditorConstructed` scheme pool, `DeckSection.Schemes`); other non-Commander modes (Sealed/Draft/Quest/...); `MomirBasic`/`MoJhoSto` (generated-deck formats using the KEEP Avatar feature; no team logic); `res/formats/**` legality data (incl. `Casual/Brawl.txt`, `Casual/Oathbreaker.txt` — decision 4 keeps banlist/legality).
- **Card-script compatibility:** keep trigger property NAMES `YourTeam` (`PlayerProperty`) and `YourTeamCtrl` (`CardProperty` + `CardScriptParser.VALID_EXCLUSIVE`); rebase semantics to self (each player is their own team) so external card-DB scripts keep parsing.
- **Networking seam:** keep `LobbySlot`/`UpdateLobbyPlayerEvent`/`GameLobby` generic; only team/archenemy fields go — no local-only assumptions baked in (networking is stripped now, re-introduced later).
- Every item: `rg` all references before deleting; build stays green after each item; then atomic local commit on `dev` (code + `[x]` + `PROGRESS.md`; NEVER `git push`).
